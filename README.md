# PayDesk Sample Application

PayDesk is a realistic enterprise expense management and reimbursement sample application built for **PUG DevCon 2026**.

The sample illustrates key application architectural patterns and provides realistic scenarios for demonstrating **Linux runtime security features** (UID/GID, Linux capabilities like `CAP_NET_RAW`, filesystem permissions, AppArmor, and seccomp) in containerized environments.

---

## Architecture Overview

The solution consists of three main projects targeting **.NET 10**:

```text
PUGDevCon2026-Demos/
├── docker-compose.yml              # Local PostgreSQL container service
├── PayDesk.slnx                    # Solution file
├── samples/                        # Sample expense CSV files for testing
│   ├── expenses_alice_2026_11.csv
│   └── expenses_bob_2026_11.csv
├── docs/
│   └── PayDesk-Sample-Spec.md      # Full application specification
└── src/
    ├── PayDesk.Core/               # Domain models, Enums, and EF Core DbContext
    ├── PayDesk.Consolidator/       # Standalone CLI binary for batch consolidation & PDF generation
    └── PayDesk.Web/                # ASP.NET Core Razor Pages web portal with Identity & ICMP Status
```

### Components

1. **`PayDesk.Core`**:
   - `ApplicationUser`: Extends ASP.NET Core Identity.
   - `ExpenseFile`: Tracks uploaded expense CSV files (`Pending` vs `Processed`), total amounts, and storage paths.
   - `ExpenseItem`: Itemized expenses (`Date`, `Description`, `Amount`).
   - `MonthlyConsolidation`: Records per-user monthly reimbursement payouts and generated PDF payslip paths.
   - `PayDeskDbContext`: EF Core PostgreSQL DbContext.

2. **`PayDesk.Consolidator`**:
   - Standalone console executable.
   - Accepts arguments: `--month <YYYY-MM> [--data-dir <path>] [--connection-string <connStr>]`.
   - Aggregates pending expenses for the target month across all users.
   - Generates high-quality itemized PDF payslips using **PdfSharpCore**.
   - Marks expense files as `Processed` and creates/updates `MonthlyConsolidation` records.

3. **`PayDesk.Web`**:
   - Built with ASP.NET Core 10 Razor Pages.
   - **ASP.NET Core Identity**: User registration and role-based access control (`Admin` and `User`).
   - **Employee Dashboard**: Upload CSV expense reports, view pending files, and download generated payslips.
   - **Admin Management**: Asynchronously invoke `PayDesk.Consolidator` executable for any month and create new user accounts.
   - **Application Status Page**: Performs an **ICMP Echo Ping** (`System.Net.NetworkInformation.Ping`) to the database host alongside a PostgreSQL connection check.

## Quickstart Guide

### Prerequisites
- [.NET 10 SDK](https://dotnet.microsoft.com/)
- [Docker](https://www.docker.com/) (for PostgreSQL)

### 1. Start the PostgreSQL Database
```bash
docker compose up -d
```
This spins up PostgreSQL 16 on `localhost:5432` with database `paydesk_db`.

### 2. Build the Solution
```bash
dotnet build
```

### 3. Run the Web Application
```bash
dotnet run --project src/PayDesk.Web
```
Open your browser to `http://localhost:5000` (or `https://localhost:5001`).

On first startup, the database tables and initial seed accounts are automatically created.

## Application Walkthrough

### 1. Submitting Expenses
1. Sign in as `alice@paydesk.local`.
2. On the **Dashboard**, choose the target month (e.g., `2026-11`).
3. Select a CSV file (e.g. `samples/expenses_alice_2026_11.csv`).
4. Click **Upload & Submit Report**.
5. The file appears in your **Pending Expense Submissions** table.

### 2. Admin Monthly Consolidation
1. Sign in as `admin@paydesk.local`.
2. Navigate to **Admin -> Monthly Consolidation**.
3. You will see pending expenses grouped by month.
4. Click **Consolidate** for `2026-11` (or use the manual trigger).
5. The web app asynchronously spawns the standalone `PayDesk.Consolidator` process. The live subprocess execution logs and exit code (0) are displayed in the UI.
6. The month is now sealed—no further expenses can be uploaded for `2026-11`.

### 3. Downloading Payslips
1. Navigate back to the Dashboard or sign in as `alice@paydesk.local`.
2. Notice the pending submissions are now cleared and moved to **Available Monthly Payslips**.
3. Click **Download PDF** to retrieve the itemized payslip generated by PdfSharpCore.

### 4. Status & Security Diagnostics Page
- Access `/Status` from the navbar (accessible to all users).
- Performs live **ICMP Ping** against the database server host.
- Performs PostgreSQL connection check and version query.

## Linux Runtime Security Demonstration Hooks

This application was specifically designed to demonstrate Linux runtime security controls:

1. **Linux Capabilities (`CAP_NET_RAW`)**:
   - The `/Status` page issues raw ICMP ping packets via `System.Net.NetworkInformation.Ping`.
   - In containerized environments where `CAP_NET_RAW` is dropped (best practice), the ICMP ping fails with `SocketException: Operation not permitted`, even while the database TCP connection succeeds.
   - This provides an ideal demonstration of capability dropping and why applications must be resilient or granted explicit capabilities.

2. **Filesystem Permissions & Non-Root UID/GID**:
   - The app stores uploads under `data/uploads/{month}` and payslips under `data/payslips/{month}`.
   - When running in containers under a non-root user (e.g. `UID 1000`), mounting host volumes with root-only permissions causes file write failures—illustrating the temptation to improperly revert to `root:0` versus properly managing file ownership and permissions.

3. **Subprocess Spawning (Process Execution & Seccomp / AppArmor)**:
   - The admin consolidation triggers `PayDesk.Consolidator` via `Process.Start`.
   - Demonstrates execution policies, seccomp filters (`fork`/`clone`/`execve`), and container filesystem boundaries.
